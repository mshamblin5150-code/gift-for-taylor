# Issue #231 print verification

The reported blank preview could not be reproduced on an iPhone or Android
device here. The reporter's phone model, OS, and browser were not captured, and
this Windows host has no connected Android device, Android emulator, or iOS
simulator. Actual iPhone Safari and Android Chrome print previews, saved PDFs,
and physical output remain unverified.

The closest available browser check used Chrome 153.0.8010.36 on Windows
10.0.26100.0. A populated September 2026 book page was generated by
`bookPageHtml` from in-memory Schedule rules, including a Staff row with a `7A`
Shift code. Playwright opened that HTML in a top-level tab from a direct button
click, then clicked its **Print this page** button. Chromium's PDF print
renderer was run at a 390 × 844 mobile viewport and a 1280 × 800 desktop
viewport. Both PDFs were nonblank, one-page, landscape Letter (792 × 612 pt).
The rendered page was visually checked; it included the month heading, dates,
Staff row, Shift code, and legend, with no Print button in the PDF.

This check exercises the new top-level print page and Chromium PDF rendering.
It does not exercise the iOS print sheet, Android Chrome, or the existing desktop
iframe print dialog. The app's complete Flutter test suite (159 tests), the
Schedule rules book-page tests (14 tests), `flutter analyze`, and a release web
build also passed.
